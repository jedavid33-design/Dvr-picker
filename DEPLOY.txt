v0.2.8 changes
1. Provider consensus
   - Episode discovery now compares all available provider results instead of automatically accepting TVmaze whenever it returns data.
   - Conflicting season/episode numbering is scored across TVmaze, EpisoDate, TMDB, and optional TheTVDB.
   - This specifically addresses Big Brother date/episode-number drift.

2. Schedule safety net
   - Each discovery date also checks the TVmaze U.S. schedule as a recovery path when an exact show's episodes-by-date endpoint returns nothing.
   - This is intended to catch valid tracked episodes such as The Great Food Truck Race that otherwise slip through an exact-provider lookup.

3. Initial backfill for newly tracked shows
   - When a show is first tracked, the frontend performs one initial backfill search for that show only.
   - The Worker widens the lookback only if needed: 30 days -> 1 year -> 2 years -> 5 years.
   - It stops at the first window containing aired episodes and sends those episodes to New from TV for approval.
   - After that one-time backfill, the normal rolling 3-day recheck/catch-up behavior takes over.

4. Sequential episode resolution when spinning
   - If a spin lands on a later episode of a tracked series, the selected result resolves to the earliest remaining episode for that same show/season up through the landed episode.
   - The wheel therefore chooses the show randomly while preserving episode order among episodes still on the wheel.
   - Watched still removes only the resolved selected episode.

TV SOURCES
- TVmaze: primary discovery + U.S. schedule safety net
- EpisoDate: active provider
- TMDB: active when TMDB_API_KEY or TMDB_READ_TOKEN is configured
- TheTVDB: optional when TVDB_API_KEY is configured
