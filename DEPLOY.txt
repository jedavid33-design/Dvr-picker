v0.2.57 changes
- Placeholder title coalescing in reconcileProviderEpisodes: when the winning
  provider record carries a stub title ("TBA", "TBD", "Untitled", "Episode N"),
  the title is filled from the best non-placeholder title in the same S/E
  bucket instead of the placeholder clobbering it. (20/20 2026-09-25: TVDB's
  "TBA" stub no longer hides TMDB's "The Salem Strangler".)
- Per-show season-number overrides (SHOW_SEASON_OFFSETS): TVDB and TMDB both
  number 20/20's 2026-27 season as 50, but ABC officially promoted it as
  Season 49 ("Season 49 Premiere", @ABC2020 2026-09-22). 20/20 now gets a -1
  season offset. Applies only to plausible season numbers (< 1000), so
  TVmaze's year-based seasons (e.g. 2026) pass through untouched. Remove the
  entry if the providers correct their data.
- Added worker-regression.test.mjs (node): 30 assertions covering the 20/20
  scenario, placeholder detection, and offset edge cases. All pass.

v0.2.56 changes
- Fixed the "have to refresh" bug for daily shows (Jeopardy!, Wheel of Fortune).
  The final prune step compared provider support across dates by show name only,
  so a morning check deleted the newest episode whenever older dates had stronger
  provider support — even though those were different broadcasts. Both prune
  filters (automatic open check and manual "Check yesterday") now only prune
  when the earlier-date result is the same season/episode, i.e. a genuine
  airdate conflict. Verified with a 9-scenario regression test.

v0.2.10 changes
- Yesterday-only ceiling: normal TV checks cannot request or surface episodes dated today or later.
- Frontend pending-card guard hides any premature same-day/future episode returned by older data.
- Initial backfill now stops at yesterday instead of including today's scheduled episodes.
- Existing Added/Dismissed review records are preserved, so already dismissed premature cards stay reviewed when their real airdate becomes eligible.
1. Provider consensus
   - Episode discovery now compares all available provider results instead of automatically accepting TVmaze whenever it returns data.
   - Conflicting season/episode numbering is scored across TVmaze, EpisoDate, TMDB, and optional TheTVDB.
   - This specifically addresses Big Brother date/episode-number drift.

2. Schedule safety net
   - Each discovery date also checks the TVmaze U.S. schedule as a recovery path when an exact show's episodes-by-date endpoint returns nothing.
   - This is intended to catch valid tracked episodes such as The Great Food Truck Race that otherwise slip through an exact-provider lookup.

3. Initial backfill for newly tracked shows
   - When a show is first tracked, the frontend performs one initial backfill search for that show only.
   - The Worker widens the lookback only if needed: 30 days -> 1 year -> 2 years -> 5 years.
   - It stops at the first window containing aired episodes and sends those episodes to New from TV for approval.
   - After that one-time backfill, the normal rolling 3-day recheck/catch-up behavior takes over.

4. Sequential episode resolution when spinning
   - If a spin lands on a later episode of a tracked series, the selected result resolves to the earliest remaining episode for that same show/season up through the landed episode.
   - The wheel therefore chooses the show randomly while preserving episode order among episodes still on the wheel.
   - Watched still removes only the resolved selected episode.

TV SOURCES
- TVmaze: primary discovery + U.S. schedule safety net
- EpisoDate: active provider
- TMDB: active when TMDB_API_KEY or TMDB_READ_TOKEN is configured
- TheTVDB: optional when TVDB_API_KEY is configured


v0.2.9 changes

- Reviewed-broadcast guard: once a show/date has been Added or Dismissed, stale alternate numbering with generic/matching metadata is suppressed during rolling rechecks.
- Existing wheel storage, order, weights, and append-at-weight-1 behavior are unchanged.
