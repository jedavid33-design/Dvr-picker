DVR WHEEL v0.2.7 - DEPLOY NOTES

Frontend
- Upload index.html, app.js, styles.css and icon.PNG to the existing GitHub Pages repo.
- No font file is required for v0.2.7. The UI now uses the system Avenir Next/Avenir stack, with platform fallbacks.
- Do not delete browser storage or reset the wheel.
- The existing wheel localStorage key remains bedtimeMovieWheel.v2. Existing items, order and weights are not migrated or recalculated.

Worker
- Replace the current Cloudflare Worker code with worker.js and deploy it.
- GET /health is public and should report version 0.2.7.

Metadata source order / reconciliation
1. TVmaze (primary)
2. EpisoDate (no-key source)
3. TMDB (keyed source when configured)
4. TheTVDB (keyed source when configured)

v0.2.7 changes
- Episode discovery now queries every configured provider for the requested date before reconciling results, instead of stopping after the first source that returns something.
- TVmaze remains the primary date authority when it has a result.
- When TVmaze is empty, keyed TMDB/TheTVDB results can override a conflicting stale EpisoDate season/episode pairing. This targets the observed Big Brother wrong-episode-number case.
- Cross-provider identity matching uses the locked TVmaze show's country/network/premiere hints to reduce same-title international collisions.
- Existing EpisoDate locks are validated and can self-heal during later discovery passes if they conflict with the anchored show identity.
- Rolling 3-airdate recheck and missed-day catch-up remain active.
- Added/dismissed cross-provider duplicate suppression remains active.
- UI typography now uses an Avenir Next/Avenir system-font stack to align more closely with OpalDay.

TMDB
- Existing Cloudflare secret TMDB_API_KEY remains supported.
- TMDB_READ_TOKEN is also supported as an alternative.
- Keep credentials only in Cloudflare Worker Variables and Secrets, never in the frontend.
- /health reports tmdbFallback:true when either TMDB credential is present.

TheTVDB
- Existing optional secret TVDB_API_KEY remains supported.
- /health reports tvdbFallback:true only when it is configured.

Wheel preservation rule
- Existing wheel localStorage remains bedtimeMovieWheel.v2.
- Approving a discovered episode appends exactly one new wheel item at weight 1.
- Discovery/rechecking never shuffles, reorders, resets, increases, decreases or otherwise modifies existing wheel items or weights.

- Stabilized the top/current-title readout to a fixed reserved height so manual wheel dragging does not shift vertically as titles of different lengths rotate under the pointer.
- Manual spin physics, wheel weights, TV discovery, and localStorage schema are unchanged.
