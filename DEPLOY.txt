DVR WHEEL v0.2.5 - DEPLOY NOTES

Frontend
- Upload index.html, app.js, styles.css and icon.PNG to the existing GitHub Pages repo.
- KEEP your existing Quicksand.ttf and OFL.txt files already in the repo. They are not included in this patch ZIP.
- Do not delete browser storage or reset the wheel.
- The existing wheel localStorage key remains bedtimeMovieWheel.v2. Existing items, order and weights are not migrated or recalculated.

Worker
- Replace the current Cloudflare Worker code with worker.js and deploy it.
- GET /health is public and should report version 0.2.5.

Metadata fallback order
1. TVmaze (primary)
2. EpisoDate (no-key fallback)
3. TMDB (keyed fallback when configured)
4. TheTVDB (keyed fallback when configured)

TMDB
- Add Cloudflare Worker secret TMDB_API_KEY for a TMDB v3 API key.
- Alternatively, TMDB_READ_TOKEN is supported for a TMDB API Read Access Token.
- Keep the credential only in Cloudflare Worker Variables and Secrets, never in the frontend.
- /health reports tmdbFallback:true when either TMDB secret is present.
- The frontend includes TMDB attribution/credits required for noncommercial API use.

TheTVDB
- Existing optional secret TVDB_API_KEY remains supported.
- /health reports tvdbFallback:true only when it is configured.

What changed in v0.2.5
- Added TMDB as the active third metadata source, ahead of TheTVDB.
- TMDB participates in show search, exact-title identity locking, episode fallback, and Franchise Watch.
- Added a rolling 3-airdate recheck on app open and on manual episode discovery so late provider metadata can appear later.
- Missed-day catch-up remains up to 30 days and is combined with the rolling recheck window.
- Added cross-provider episode fingerprinting so an episode already Added or Dismissed stays suppressed even if a later recheck finds the same episode through a different provider.
- Existing tracked shows are allowed to learn tmdbId automatically without being removed/re-added.

Wheel preservation rule
- Existing wheel localStorage remains bedtimeMovieWheel.v2.
- Approving a discovered episode appends exactly one new wheel item at weight 1.
- Discovery/rechecking never shuffles, reorders, resets, increases, decreases or otherwise modifies existing wheel items or weights.
